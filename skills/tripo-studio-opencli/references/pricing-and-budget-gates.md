# 算力计价与预算门禁

本页记录 `scripts/tripo_pricing.py` 使用的 Studio 计价基准和 `scripts/tripo_ledger.py` 的预算锁账流程。线上价格和会员活动会随网页更新变动，每次提交前一律以页面实时标价、本源资格和用户本次批准额度为准。

## 生成计价参考

高细节模式（`--tier hd`）单份基价按是否带贴图二选一：**有贴图 25 积分，无贴图 15 积分**。

- **结构附加项**：四边面 +5，分部件 +30，SmartPoly +20。提交前先核对页面当前是否开放对应组合。
- **贴图附加项（开启贴图时）**：`detailed` +10，`extreme` +20，开启 `--pbr` 再 +5。
- **几何细节附加项**：高版本 `detailed` 几何 +15。
- **常见组合示例**：有贴图 + `detailed` 贴图 + `detailed` 几何合计 `25 + 10 + 15 = 50` 积分；有贴图 + `extreme` 贴图 + PBR + `detailed` 几何合计 `25 + 20 + 5 + 15 = 65` 积分。

Smart Mesh（`--tier smartmesh`）单次基价 **100 积分**，开启四边面无额外加价。符合条件的账户试用可抵一次 100 积分，但需要同时核对当前项目的实时资格。多视图生成按一次计价，非批量 Smart Mesh 的 2 档或 4 档面数多输出同样按一次计价，批量模式按输入图数量累乘。

## 后处理与导出计价参考

| 操作 | 参考计价与核对要点 |
|---|---|
| `segmentation`（拆分） | 40 积分 |
| `fill-parts`（补全） | 以当前页面实测标价为准（当前版本页面显示为 0） |
| `retopology`（重拓扑） | 三角面 5 积分，四边面 10 积分；开启 `--smart-poly` 另加 30 积分（合计 35 / 40） |
| `smart-uv`（智能 UV 生成） | 20 积分；合格试用可抵扣；显式请求下一候选按页面免费窗或 10 积分实时核价 |
| `texture`（重新贴图） | 10 基价 + `detailed` 10 或 `extreme` 20 + `--ref-image` 风格参考 5 |
| `texture-edit`（提示词重绘预览） | 5 积分；符合会员条件时页面可显示为 0，按页面实测标价核对 |
| `texture-edit` 保存应用 | 价格契约待核清，目前保持干跑与准备检查，待价格明晰后再启用自动提交 |
| `smart-uv` 保存应用 | 页面未标明单价，需单列步骤并获得用户对预留上限的明确同意 |
| `texture-pbr`（PBR 贴图） | 5 积分 |
| `texture-upscale`（贴图放大） | 4K 为 10 积分，8K 为 20 积分；4K 试用需核实本源资格，用户批准付费且页面跳过试用时传 `--skip-upscaler-trial` |
| `rigging`（自动绑定） | 20 积分；后续动作卡片另立步骤并按批准的 `--retarget-credit-cap` 预留 |
| `export` / 官方 Bridge | 自有模型 0 积分；非自有公开模型 5 积分（需用户明确批准并加 `--allow-nonowner-spend`）。零积分导出同样计入操作与下载次数 |

## 预算锁账与执行纪律

1. **先干跑后准备**：默认执行估算或 `--prepare-only`，观察页面控件和实时标价。需要上传参考图做准备验证时，在获得上传许可后显式加 `--prepare-upload`。
2. **明确初始化任务上限**：获得用户批准后，立即初始化账本任务，分别写清积分、操作、下载和试用四项上限：
   ```powershell
   python scripts/tripo_ledger.py init-task `
     --task-id <task_id> `
     --budget-cap <积分上限> `
     --max-submissions <操作次数上限> `
     --download-cap <下载次数上限> `
     --trial-cap <试用项=次数> `
     --region cn --note "<本次任务说明>"
   ```
   一次计划内的生成、后处理、预览保存、导出或动作重定向各占一次受控步骤（零积分步骤也计入）；只读查询和纯本地检查不占额度。
3. **价格精确对齐**：执行提交前要求页面观测价格与本地估算完全相等（`observed == estimated`）。页面标价高于或低于预估时，立刻停下把差异报给用户重新确认。
4. **先记提交再点击**：驱动在触发真实点击前先把步骤持久化为 `submitting`，拿齐唯一操作编号和回执后再更新为 `submitted`。遇到超时、断网或回执残缺时按 `unknown` 冻结任务，停下来核查原项目和原回执，保持零自动重试。
5. **本地预留与人工复核**：`--unpriced-apply-cap` 和 `--retarget-credit-cap` 属于本机账本的保守预留，用于控制本地预算统计。任务进入 `halt` 状态后保持原记录完好，确认完现场事实并由用户明确批准解锁该项 `halt` 后，再运行 `tripo_ledger.py clear-halt --task-id <id> --human-review --reason "<原因>"`。
6. **统一对账**：累计消耗同时统计脚本账本记录和已知的用户手动云端操作，按唯一 `operator_id` 去重。用户说「继续」或「修好」时沿用原有数值上限，额度用完时先整理完本地成果与具体下一步方案，再请用户批准新的增量额度。
